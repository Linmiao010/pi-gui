## 三、功能一：原生 LaTeX 数学公式渲染

### 3.1 集成数学公式渲染引擎

使用以下依赖：

- `remark-math`
- `rehype-katex`
- `katex`

将其集成到现有 `react-markdown` 渲染链路中。

保持 `remark-gfm` 以及原有 Remark/Rehype 插件正常运行。

正确引入：

```tsx
import remarkMath from "remark-math";
import rehypeKatex from "rehype-katex";
import "katex/dist/katex.min.css";
```

注意：

- 不要直接替换整个 Markdown 渲染器。
- 不要破坏现有工作区文件链接及其点击跳转行为。
- 不要改变原有 Markdown 组件结构或代码高亮逻辑。
- 数学公式必须在 pi-gui 原生聊天窗口内显示，不依赖外部 Markdown 预览器。

### 3.2 支持的数学公式格式

必须支持四种分隔符：

**行内数学公式：**

```latex
$E=mc^2$
```

```latex
\(E=mc^2\)
```

**块级数学公式：**

```latex
$$
i\hbar\frac{\partial \psi}{\partial t}
=
\hat{H}\psi
$$
```

```latex
\[
i\hbar\frac{\partial \psi}{\partial t}
=
\hat{H}\psi
\]
```

注意：`remark-math` 对 `\(...\)` 和 `\[...\]` 的兼容性不能仅通过添加依赖假定已经实现。应设计安全的预处理层或 AST 转换层，确保这些分隔符得到正确处理。

### 3.3 保护代码内容

数学公式分隔符转换不得影响：

- Markdown fenced code blocks
- Markdown inline code
- 含有 LaTeX 示例的代码块
- 转义后的美元符号
- 普通文本中的美元金额
- Markdown 链接、GFM 表格等其他语法

例如：

```python
formula = r"$E=mc^2$"
```

上述内容必须继续显示为 Python 代码，而不是将字符串中的数学公式渲染。

禁止使用简单的全局正则替换，对完整 Markdown 文本直接执行不考虑语法上下文的分隔符转换。

优先使用 Markdown Token、AST 或具备上下文感知能力的解析方案。

### 3.4 数学公式排版要求

支持常见 LaTeX 数学表达式，包括：

- 上下标、分数、根号
- 积分、求和、极限
- 矩阵与行列式
- 希腊字母
- `aligned`、`cases`、`pmatrix` 等数学环境
- 多行公式

公式需要正确适配深色和浅色主题。

较长的块级公式应支持横向滚动，不能撑破聊天窗口布局。

### 3.5 流式输出与异常容错

AI 回复可能通过流式输出逐步生成：

```text
$
```

```text
$$
```

```text
$$
\int_0^
```

在公式尚未闭合时：

1. 不得导致 React 渲染异常。
2. 不得出现整个消息消失或反复闪烁的情况。
3. 尽量保持原始内容可见。
4. 公式完整后自动切换为正常排版。
5. 不得影响已有流式消息更新逻辑。

对无法解析的数学命令，应保留适当的原始文本或显示非阻塞错误状态。

不得因为单条公式错误导致整个聊天窗口渲染失败。

## 四、功能二：聊天消息复制

### 4.1 AI 回复一键复制

在每条 AI 消息底部的现有操作栏中增加 `Copy` 按钮。

位置建议：

```text
[Copy] [Fork]
```

功能要求：

- 复制当前 AI 回复的完整原始 Markdown。
- 保留代码块及语言标记。
- 保留 LaTeX 公式源码。
- 保留 GFM 表格格式。
- 保留原始换行和 Markdown 结构。
- 不复制 HTML 标签或渲染后的 KaTeX DOM。
- 不包含工具输出、其他消息或界面按钮文本，除非它们原本属于该消息的 Markdown 内容。

使用当前消息的数据源文本，不要从渲染后的 DOM 提取。

按钮在流式输出期间也应可用，复制当前已经收到的文本。

### 4.2 用户消息一键复制

为每条用户消息增加 `Copy` 按钮。

要求：

- 复制原始用户文本。
- 保留 Markdown 格式及换行。
- 对包含图片或附件的消息，仅复制文本部分，不尝试复制附件二进制内容。
- 复用现有消息操作栏样式，避免改变用户消息气泡布局。

### 4.3 Markdown 代码块复制

为所有 fenced code blocks 增加独立的代码复制按钮。

建议交互：

```text
┌────────────────────────────────────┐
│ python                      Copy   │
├────────────────────────────────────┤
│ def hello():                       │
│     print("Hello World")           │
└────────────────────────────────────┘
```

要求：

- 将按钮放在代码块右上角。
- 仅复制代码内容，不包含 Markdown 围栏标记。
- 保留原始缩进与换行。
- 不复制语言标签。
- 不修改已有语法高亮行为。
- 与现有代码滚动区域兼容。
- 代码块内含 `$...$` 等字符串时，依旧按代码内容复制。

### 4.4 复制状态反馈

所有复制按钮使用一致的交互反馈：

| 状态 | 显示 |
|---|---|
| 默认 | Copy |
| 成功 | Copied |
| 失败 | Copy failed |

实现要求：

- 优先使用现有剪贴板封装；否则使用 `navigator.clipboard.writeText()`。
- 复制成功状态短暂显示后恢复。
- 复制失败时不能虚报成功。
- 不吞掉异常，应提供用户可感知的错误反馈。
- 复制过程中不能阻塞聊天输入。
- 组件卸载时避免遗留异步状态更新或定时器。

### 4.5 可访问性要求

所有复制按钮必须：

- 使用语义化 `<button type="button">`。
- 设置明确的 `aria-label`。
- 支持 Tab 导航。
- 支持 Enter 和 Space 激活。
- 具有可见的键盘焦点样式。
- 不能依赖鼠标悬停才能通过键盘访问。
- 不能干扰消息文本选择。
